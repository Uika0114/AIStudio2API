# 可移植工具历史与签名来源

显式 `playground/` 与 `build/` 生成请求会在请求副本内检查工具历史签名。Chat、Responses（含后台与压缩生成）及 Gemini 使用同一边界。

- 已知且匹配当前 canonical 模型/通道的显式签名保留；有效显式值不被缓存覆盖。
- part 与 function call 携带冲突签名、已知跨模型/通道签名，以及已知 strict 来源转为裸名 auto，继续拒绝。
- 仅 FunctionCall 所在 part/call 的非空签名在当前来源索引完全未知时，清除该签名。随后优先恢复完整工具调用键匹配的同模型/通道缓存；没有当前路由缓存、但该调用已知属于其他路由时仍拒绝。若 routed 值仍在而独立 origins 记录已淘汰，精确的路由缓存键可作为该恢复值的来源证据；已有不匹配 origins 仍拒绝，Assistant 不适用此例外。
- 无可恢复签名且无已知冲突时，保留工具语义并由既有编码器写入 `skip_thought_signature_validator`。不透传未知不透明值、不重新执行工具，也不删除消息、参数或工具结果。

来源和缓存只保存在当前进程，重启或有界淘汰后可能变成未知；未知不等于已经证实是旧签名。转换保留可移植消息和工具语义，但不保证恢复隐藏推理状态，也不保证上游接受每一种历史。此规则不依赖账号、会话 ID、客户端或模型名单。

非工具的文本/thinking/媒体/签名专用 part 不自动去签名。Assistant 保持原有文本降级及来源拒绝，不接入此转换。Anthropic `/v1/messages` 的裸名适配不接入共享签名恢复；Responses 中丢失的 `previous_response_id` 内容也不会由此重建。

通道启用是独立限制：默认只启用 Playground；Build/Assistant 必须显式启用才可调度，关闭请求不自动换成 Playground。兼容实现和离线测试不构成启用通道或真实上游调用的授权。
